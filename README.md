# KTX 취소표 감시 봇

코레일 KTX 열차의 취소표를 감시하다가 좌석이 나오면 **예약만 선점**하고
텔레그램으로 알려준다. 결제는 하지 않는다.

---

## 감시할 열차 바꾸기

`config.json` 파일만 고치면 된다. 목록에 항목을 추가하면 여러 열차를 동시에 감시한다.

```json
{
  "감시목표": [
    {
      "이름": "부산 출장 가는 편",
      "출발역": "서울",
      "도착역": "부산",
      "날짜": "2026-09-20",
      "시각": "18:30",
      "어른": 1,
      "어린이": 0,
      "예약대기": true,
      "사용": true
    }
  ]
}
```

| 항목 | 설명 |
| --- | --- |
| `이름` | 알림에 표시될 이름. 아무거나 |
| `출발역` / `도착역` | `"서울역"`이 아니라 `"서울"`. 역 이름만 |
| `날짜` | `2026-09-20` 형태 |
| `시각` | `18:30` 형태. **출발 시각이 정확히 일치하는 열차만** 잡는다 |
| `어른` / `어린이` | 인원수. `경로`, `유아`도 쓸 수 있다 |
| `예약대기` | `true` 면 매진일 때 예약대기도 신청한다 |
| `사용` | `false` 로 두면 그 목표는 건너뛴다 |
| `열차번호` | 선택. 같은 시각에 열차가 여럿일 때만 쓴다 (예: `"101"`) |

고칠 때 주의할 것:

- 항목 사이에는 쉼표 `,` 를 넣고, **마지막 항목 뒤에는 쉼표를 넣지 않는다**
- 큰따옴표 `"` 를 빼먹지 않는다
- 숫자(`어른`, `어린이`)와 참/거짓(`true`, `false`) 에는 따옴표를 붙이지 않는다

---

## 감시 멈추기

저장소 상단 **Actions** 탭 → 왼쪽에서 **KTX 취소표 감시** 선택 →
오른쪽 `⋯` 버튼 → **Disable workflow**.

다시 켤 때는 같은 자리에서 **Enable workflow**.

---

## 잡은 열차를 다시 감시하기

예약에 성공하면 봇이 `state.json` 에 기록을 남기고 그 목표를 더 이상 건드리지 않는다.
다시 감시하려면 `state.json` 의 `예약완료` 안에서 해당 줄을 지운다.

```json
{
  "예약완료": {
    "서울>부산 2026-09-20 18:30": { ... }   ← 이 줄을 통째로 지운다
  },
  "예약대기": [],
  "없는열차": []
}
```

`state.json` 은 봇이 쓰는 파일이다. `config.json` 은 건드리지 않으니 둘이 충돌하지 않는다.

## 동작 방식

- 15분마다 워크플로가 실행되고, 각 실행은 25분간 살아 있으면서 25초 주기로 조회한다
- 새 실행이 뜨면 이전 실행은 자동 종료된다 (겹치는 10분이 완충 구간)
- 목표와 목표 사이에는 3초를 쉬어 요청이 몰리지 않게 한다
- 좌석을 잡으면 1분 간격으로 3번 알린다
- 열차가 이미 출발했으면 그 목표를 스스로 종료한다

## 알아둘 것

- 코레일 예약은 **선점 후 10분 안에 결제**하지 않으면 자동 취소된다
- 코레일·SRT 는 이용약관에서 자동화 프로그램 접근을 금지하고 있다.
  본인 탑승 목적으로만 쓰고, 조회 주기를 더 짧게 바꾸지 말 것. 계정이 정지될 수 있다
- 표를 웃돈 받고 되파는 것은 철도사업법 위반이다
- 이 봇은 코레일의 비공식 API(`pykorail`)를 쓴다. 코레일이 서버를 바꾸면
  예고 없이 멈출 수 있다. 그럴 때는 `pip install -U pykorail` 로 최신 버전을 쓰면 되는 경우가 많다
